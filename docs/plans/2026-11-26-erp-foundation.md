# ssERP (Super Simple ERP) — Foundation Plan

**Goal:** Open-source ERP / Inventory / Billing with per-unit Serial/IMEI lifecycle tracking.
Lifecycle: Vendor → Purchase → Inventory → Sales → Customer → Warranty/Service.
**Spec:** the product brief in `docs/SPEC.md` (user's original Bengali brief, summarized there).
**Repo:** https://github.com/bemoshiur/Super-Simple-ERP-ssERP (MIT, open source, self-hostable, Vercel-deployable).

## Global Constraints (binding on every task)

- **Stack:** Next.js 16 (App Router, TypeScript strict), React 19, React-Bootstrap + a commercial admin-theme starter shell already copied into `src/` (layouts, scss, `DataTable`, `PageBreadcrumb`, etc.; replaced by ssERP's own shell in Task 16, see docs/THIRD_PARTY.md). Package manager: npm. Node 20+.
- **Database:** Neon Postgres recommended (`drizzle-orm` + `@neondatabase/serverless`, `neon-serverless` **Pool** driver with `ws`); plain PostgreSQL is also supported via `drizzle-orm/node-postgres` + `pg` (see `docs/DATABASE.md`, `DB_DRIVER`). Real transactions must work on both. One helper `getDb()` in `src/server/db/index.ts`. Env var: `DATABASE_URL`. Second env var: `AUTH_SECRET` (>=32 chars).
- **Migrations:** generated by `drizzle-kit generate` into `drizzle/` and **committed**. The installer applies them with `drizzle-orm/neon-serverless/migrator`. No hand-run SQL for users.
- **Multi-tenant ready from day 1:** every business table has `company_id uuid not null` (FK `companies.id`); tables that are branch-scoped also have nullable `branch_id`. Every query/mutation takes `companyId` from the session context — never from client input. v1 ships with exactly one company + one "Main" branch.
- **Money:** `numeric(14,2)`; never JS float arithmetic on money. Provide `src/server/money.ts` (integer-minor-unit helpers: `toMinor`, `fromMinor`, `fmt`) and use it. Currency symbol configurable in `settings` (default `৳`).
- **Serial integrity (the core feature):** each physical unit is a row in `product_units` (serial/IMEI unique per `(company_id, serial_no)`). Status enum: `in_stock | sold | returned_to_vendor | in_service | damaged`. Every state change writes an append-only `unit_events` row (type, ref table/id, actor user, price, note, timestamp). Stock quantity of a serial-tracked product is `count(units in_stock)` — never a separately-edited number. Non-serial products use `stock_movements`.
- **Mutations** are Next.js Server Actions or Route Handlers validated with `zod`, run inside DB transactions, check permission (`can(session, 'module.action')`), and write an `activity_log` row.
- **Auth:** email+password (`bcryptjs`), signed JWT (`jose`) in an httpOnly, sameSite=lax, secure-in-prod cookie. Roles: `admin`, `manager`, `salesman` seeded + custom roles; permissions are string keys `module.action` stored per role.
- **Installer:** if no `installed` flag in `settings`, every page except `/install`, `/_next`, static redirects to `/install`. Never allow `/install` to run again once installed (403).
- **UI:** reuse the template look. Remove demo content/branding (theme name, ecommerce dashboard, demo images, landing). App name "ssERP". Bengali-friendly: UTF-8, font stack must render Bengali (add `Noto Sans Bengali` via `next/font` fallback).
- **Licensing:** the local theme package folder (`<Name>_v<version>/`) is a licensed commercial theme and is git-ignored; never commit it or copy template pages not needed. All new code is MIT.
- **Quality:** `npm run build` and `npm run lint` pass at the end of every task. Tests: `vitest` for pure logic (money, permissions, serial state machine, invoice totals). DB-touching code is verified by a `scripts/smoke-*.ts` run against `DATABASE_URL` when available; if no DB is available, say so in the report rather than faking it.
- **Commits:** small, conventional commits on branch `feat/erp-foundation`. End each commit message with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Task 1: Database layer, schema, migrations, money helper

Create `drizzle.config.ts`, `src/server/db/index.ts` (`getDb()`, Pool + ws, singleton per process), `src/server/money.ts` (+ vitest tests), and the full schema in `src/server/db/schema/` (one file per domain, re-exported from `schema/index.ts`):

- core: `companies`, `branches`, `settings` (key/value per company, includes `installed`, `currency_symbol`, `invoice_prefix_sale`, `invoice_prefix_purchase`)
- identity: `users`, `roles`, `role_permissions`, `activity_log` (user, action, entity, entity_id, before/after jsonb, ip, created_at), `record_history` (entity, entity_id, changed_by, diff jsonb)
- catalog: `categories`, `brands`, `products` (name, sku unique per company, category, brand, `track_serial bool`, `warranty_months int`, purchase_price, sale_price, `low_stock_threshold`, active), `stock_movements` (for non-serial)
- parties: `vendors`, `customers` (name, phone, email, address, opening_balance, notes, active)
- purchasing: `purchases` (invoice_no unique per company, vendor, date, subtotal, discount, total, paid, due, status), `purchase_items` (product, qty, unit_cost), `product_units` (company, product, serial_no, purchase_item_id, vendor_id, purchase_price, status, warranty_months, location, created_at), `unit_events`
- sales: `sales` (invoice_no unique per company, customer, date, subtotal, discount, total, paid, due, status, created_by), `sale_items` (product, qty, unit_price, unit_cost_snapshot, `unit_id` nullable for serial items), `sale_returns`, `sale_return_items`, `purchase_returns` (+items)
- accounting: `accounts` (type cash|bank|mobile, name, opening_balance), `payments` (direction in|out, account, party type/id, ref type sale|purchase|expense|income|manual, ref id, amount, method, date, note), `expenses` & `incomes` (category, amount, account, date, note), `expense_categories`
- service: `service_tickets` (unit_id, customer_id, status, issue, resolution, opened_at, closed_at) — schema only now, UI later.

Add sensible indexes (serial lookup, invoice_no, foreign keys, `(company_id, status)` on units). Run `drizzle-kit generate`, commit `drizzle/`. Add `vitest` + `npm test` script.
**Acceptance:** `npx drizzle-kit generate` is clean; `npm test` passes money tests (rounding, fmt with ৳, sum of 0.1+0.2 == 0.30); schema typechecks (`npx tsc --noEmit`).

## Task 7: Sales, billing, payments, returns

Sales invoice form with a scan-first UI: focus input accepts a serial/IMEI (Enter submits), looks up an `in_stock` unit for the company and adds the line with the product's sale price (editable), rejects unknown/sold/non-stock serials with a clear message; non-serial items by product+qty with stock check. Customer picker (+ walk-in), discount, multiple payments (cash/bank/mobile) in one invoice, due computed. Save in one transaction with row locking on units (`FOR UPDATE`) to prevent double-selling: units → `sold` + `unit_events(sold, price, customer)`, `sale_items.unit_cost_snapshot` = unit purchase price (for profit), payments recorded, activity logged. Invoice number from per-company sequence + prefix setting. Invoice view with print stylesheet (A4 and 80mm thermal) and "Download PDF" via browser print-to-PDF button. Sales return/refund: pick invoice lines, units back to `in_stock` (or `damaged`), refund payment out, return doc. Customer due collection with partial payments.
**Acceptance:** concurrent double-sell of the same serial is rejected (test or smoke); totals/profit computed with money helpers (vitest); build passes.
